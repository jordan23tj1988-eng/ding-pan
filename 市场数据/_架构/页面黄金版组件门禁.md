# 页面黄金版主判断组件门禁

## 目的

七个复盘子页面的主判断组件统一遵循 `D:\黄金对照版717\` 的显示方式。黄金版是只读视觉基准；页面内容可根据当日真实模型优化，组件层级不能漂移。

## 固定结构

```text
hero
├── kick       页面名称 / 当前判断 / 截止日期
├── h1         当日主判断；可用 em 强调后半句
├── p          本页阅读说明（方法与信息职责，不放证据清单）
└── stance     当前状态 pill（各页面按职责显示 3 或 4 枚）
```

主判断组件禁止出现：

- `回看完整判断与证据`
- `原判完整依据、反证与条件`
- `证据回链`
- 指向 claim/evidence 的链接或折叠详情

证据的保留位置：页面正文的 claim 区域、来源审计折叠、audit JSON。删除 hero 内入口不等于删除证据。

## 工程规则

1. 组件结构只从 `review_pages.py` 的 `GOLDEN_HERO_ROUTES` 和 `HERO_GUIDES` 产生，不在产物 HTML 上手改。
2. 新增页面先加入黄金结构回归测试，再加入白名单；不得复制一套局部 hero。
3. 当日内容只能来自当日页面模型和权威真源；缺失字段显示 `—`，不为了填满 pill 编造数字。
4. 概览页可读层（reading spine、矩阵、折叠等）与 hero 契约分离；修改概览页不自动扩散其它版式。
5. 其他六页按逐页点名、逐页截图、逐页测试、逐页发布；未验收页面不得进入正式发布目录。
6. 每次渲染改动必须执行：
   - `python -m pytest tests/test_review_pages_hero_golden.py -q`
   - `python -m pytest tests/test_review_pages*.py -q`
   - `python limitup数据核对.py <日期>`
   - 发布前再执行 P1/P2/P3 与 C1-C28 哨兵。
7. 完成后登记 `_变更总账.md`，并核对发布版、黄金版和历史归档未被写入。

## 回归判定

- 七页生成结果均为 `status=ok`；
- 每页 hero 子节点顺序与黄金版一致；
- hero 内无 `a`、`details`、证据入口文案；
- 页面其它层仍保留每条 claim 锚点和来源审计；
- 任何门禁失败均视为未完成，不得通知发布成功。
