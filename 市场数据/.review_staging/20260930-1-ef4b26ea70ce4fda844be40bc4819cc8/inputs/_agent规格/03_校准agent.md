# 03 · 校准 agent 规格

## 定位与操盘价值
Claude 训练回路的"结算台"。拿今天真实结果，结算**昨晚 Claude 自己的预判**：哪些验证、哪些打脸，逐条记在案。这是我长记性、变强的唯一入口——不结算就不进化。

## 触发/时点
- 傍晚场最先跑（先结算昨日，再做今日认知）。
- 早盘场：用集合竞价结果对照昨晚"竞价强弱预判"。

## 输入
- 昨日预判 `_学习/推演_{d-1}.json`（Claude 的可证伪预测）。
- 今日真实结果：`{d}/analysis.json`、竞价快照、涨停/连板兑现。

## 步骤
1. 逐条取昨日预测（情绪升降、主线续断、龙头接力、竞价强弱、具体票兑现）。
2. 对每条判**验证/部分验证/证伪**，附真实数据证据（不美化、不找补）。
3. 归因：为什么对/为什么错（环境闸门？题材证伪？席位误判？）。
4. 写入在案库 `_学习/在案_校准.jsonl`（append-only，每条带日期/预测/结果/对错/归因/A-C档）。

## 产出
- `_学习/校准_{d}.json`（今日结算清单 + 命中率）
- 追加 `_学习/在案_校准.jsonl`

## 自审清单（第一层）
- [ ] 是否**只用真实结果**判定，无事后美化/挑有利证据？
- [ ] 每条是否给了可核对的数据证据？
- [ ] C档预测（竞价类）是否只用实盘真实兑现结算，不反推？
- [ ] 打脸的是否如实记，不轻描淡写？

## A档/C档
- 结算依据全是已发生的真实结果 = **A档事实**；但被结算的预测本身可能是 C档判断，需保留其原始 A/C 标签以便提炼分别处理。

## 复用现有 / 接口
- 复用：竞价验证.py、verifier.py。
- 上游：昨日推演 + 今日分析；下游：提炼优化（喂在案）。
