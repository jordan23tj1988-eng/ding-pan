## 〇、改动三合一SOP(最高执行规则)

用户提优化 → 直接改实现没问题,但一次改动=完整走完四步,缺一步不算改完:

1. **定爆炸半径**:在本图找到要动的节点(文件/字段/段标题/锚点/口径),列出全部下游消费者。动"口径/分数/接口"还必须grep全站引用处(口径切换全站一致铁律)。找不到节点=本图缺边,先补图再动手。
2. **增量改**:读盘上最新版做底版(多会话并行,禁用对话记忆整篇重写);只做锚点式局部修改;中文.py用bash heredoc;长文件=python整读整写/tmp+读回比对。
3. **链路重走**:重走范围按〇.1分级表定;被改节点在"重跑顺序不变式"(第一节)里处于哪一环,就从那一环起把下游重跑,禁止只跑单步;末尾必过 复盘一致性哨兵.py + 渲染目检。改的若是规则文件(skill/prompt/agent规格/规范),按第四节"三处联动"同步其余两处。
4. **登记**:在 `_变更总账.md` 追加一条(编号/日期/动机/触点文件/下游已重跑清单);牵动链路结构则同步本图。★哨兵C8会核对:正式.py/agent规格/规范的mtime晚于_变更总账.md=FAIL"改了没登记"——登记是链路放行条件,不是可选礼貌。(哨兵现有C1-C7:缺口词/对账/新鲜度/覆盖/结算/HTML结构/陈旧嵌卡)

| **中改** | 脚本逻辑/字段/阈值/口径/段结构 | 动口径先grep全站引用;从被改节点起链路重走到哨兵;阈值类先跑对应回测(三窗=冰点触发器回测.py);登记总账 |

## 一、重跑顺序不变式(铁的顺序,从中间改=该点以下全部重走)

```
取数(市场数据下载) → 模拟盘settle → 涨停复盘量化链(温度→四维→质量prep/enrich/fit→荐票→温度--card)

→ 写 judgment_{d}.json → 竞价池结算归档--inject → 模拟盘引擎 dashboard {d}
→ 生成盯盘台.py {d} → 模拟盘引擎 inject {d} → 复盘一致性哨兵.py {d} → 渲染目检
```

- **bars_cache 变过** ⇒ 必须走坑19补数SOP:补齐→结算重跑→dashboard(重算浮盈)→旁路重mark净值(settle有done守卫)→write_status→bench删脏重算→inject→judgment stale叙述逐处清扫→哨兵。
- **judgment 变过**(哪怕只改一个body) ⇒ 归档inject→dashboard→生成盯盘台→模拟盘inject→哨兵,一步不少。
- **任何重渲染** ⇒ 必补 模拟盘引擎 inject(生成盯盘台每次重建都冲掉PAPERTRADE段;07-12/07-13事故)。

## 四、规则文件三处联动(改规矩必同步)

同一条行为规则活在三处:**skill(sentiment-review-system) ↔ 定时任务prompt(sentiment-daily-review / sentiment-morning-auction / sentiment-weekly-training) ↔ _agent规格/*.md+四份规范**。改任何一处的规则,必须检查另外两处是否载有同一规则并同步,否则下次跑链路时新旧规则撞车。改skill用save_skill overwrite且先读缓存最新版;改prompt用update_scheduled_task且先Read当前SKILL.md。改完都要登记 `_变更总账.md`。

**★版本戳规则(乐观锁,防多窗口撞车)**:每个规则文件头部带版本号——skill=标题vX.X;两个定时prompt=正文首行"[prompt版本戳 vX 日期]";四份规范/本图=自带版本行。改前核对盘上版本是否等于自己读到的版本(不等=别的窗口动过,重读并入);改后版本+1并登记总账。后写的一方发现版本对不上=强制重读,这是防覆盖丢改动的最后一道闸。


## 高危边档案 · 2026-07-16 两条事故教训(每次改脚本前必读)

### 高危边#E1: 台账脚本 --from-data 缺日期=静默跳过当日日块
- **现象**:`龙虎榜台账.py --from-data`/`涨停复盘台账.py --from-data` 若漏带 YYYYMMDD,`d=next(取数字,None)=None`,`if d and "--from-data"` 判False→跳过当日日块构建,只重注入旧存档,退出码0无报错,页面停在昨日。
- **已加防御**:①两脚本 main 已加守卫(缺日期→报错sys.exit(2));②哨兵 **C9** 核对三台账最新日块日期(涨停/龙虎榜=d,竞价=dprev)。
- **铁律**:跑任何 `*台账.py --from-data` 必带当日日期;出页后哨兵C9是最后闸门。

### 高危边#E2: ★Edit工具在本挂载盘会截断文件——改.py一律用python整写
- **现象**:2026-07-16用Edit给3个脚本加代码,每次都把插入点之后的文件内容**全部截断**(py_compile可能仍过因截断处恰是合法语句,但功能全丢+__main__丢失)。
- **铁律**:★在本环境改任何脚本/长文件,**禁用Edit工具**,一律 `python3 读整文件→字符串处理→写回` 或 bash heredoc 整写;改完必须 `py_compile` + 跑一次验证功能(不能只看编译过);多次heredoc追加要防重复(用去重/截断锚点)。

### 高危边#E3: 首页观察点obs卡markup漂移=晨场脚本静默解析0只(2026-07-17流血)
- **现象**:`竞价快线.py` 跑出"取到实时 0/0"、首页每张obs卡"今晨竞价"停在"—"。根因=首页观察点卡片被(他窗)从 `<div class="obs-nm">名<span class="mut">代码</span></div>` 改成 `<span class="obs-nm">名 <span class="mut">代码</span></span>`(+类型从tag2挪到 `obs-pos`),而 竞价快线.parse_watchlist 与 竞价上首页.inject_obs 两处parser仍按旧div正则→匹配0只,退出码0无报错。
- **已加防御**:两脚本obs-nm正则均兼容 div/span 两版(按 `</span></span>`/`obs-pos` 定界),类型优先读obs-pos回退tag2,名称新增mut前纯文本回退;旧div分支保留不破历史页。
- **铁律**:任何会话改首页观察点卡片HTML结构(生成盯盘台/agent直写),必同步这两个parser;晨场若再见"0/0"或整屏"—"先查obs卡结构。
- **★三件套缺口(建议补)**:尚未加机器检查。建议哨兵新增 **C10**:若 `竞价验证_{dnext}.json` 明细数>0 但当日judgment index的 obs-jj 全为"—/未采集"→FAIL。本次为不在盘中扰动刚通过的哨兵,暂以文档+双parser防御兜底,C10留作下一次非盘中时段补。
