FINDING 01
没有“可证明的 alpha”

五路合计 823 笔、胜率 36.6%、均收 −0.70%；唯一正均收是涨停质量 +0.16%（n=89）。系统有净值曲线，却没有 R 倍数、期望值、置信区间、基准相对——赚亏都说不清是能力还是运气。

FINDING 02
可靠性是最大短板

9/7 以来 25 个交易日有 7 天没有可发布复盘（9/14–9/18 连续 5 日全断）；唯一 OS 级兜底调度 StockDailyChain 处于禁用；6 个 cron 停用；watchdog 连续失败 15 次。

FINDING 03
门禁在“放行”而不是“拦截”

0. 结论先行

工程实现：2.3 / 5（L2.5）

骨架完整、发布可追溯，但“靠人守”的成分仍然很高：调度单点、无 CI、无保留策略、生产目录无版本库、巨石文件 2,000 行。

  • 强：release manifest + sha256 + 4,564 个 source hash，页面可追溯到源文件；数据契约与质量标记完整。
  • 弱：.review_staging 已 ≥7.3GB / 35.6 万文件；95 处静默 except；执行历史只留 1,000 行（约 17 天）。

复盘能力：2.6 / 5（L3.5）

“怎么想”已经成型：五路独立、总审裁决、盲区声明、结构化可证伪预测；短板在“怎么知道自己想对了”。

  • 强：fact 卡 17/17 quality=ok；总审 D1–D4 分歧裁决 + 指派 + 盲区；预测带 field/op/threshold。
  • 弱：预测 58% 不可判定或模糊；105 个预测 id 重复结算、49 个状态互相冲突；165 条自指派只有 27 条完成。
一句话根因：这套系统的“认知生产能力”远强于“认知结算能力”。每天产出大量判断、证据、任务，但没有一个强制闭环把它们变成可验证、可累计、可复利的资产——于是判断越来越精致，系统却没有变强。

1. “行业顶级”到底指什么

先把标准钉死，否则“顶级”只是形容词。以下 5 条硬门槛，任何一条不满足都不算顶级。

硬门槛定义本系统现状判定
可复现任一历史页面可由 manifest 逐字节重建；判断只使用决策时点前数据release 有 page_hashes + source_hashes，本项接近达标；但 as-of 哈希测试当前为红，零后视镜只在注释层声明接近
可度量每个判断都落到唯一、幂等、可结算的账本；有基准、有置信区间、有校准账本分散在 7+ 个 jsonl；预测重复结算；无置信区间/校准曲线未达
可靠≥95% 交易日按时交付；失败必告警；无静默断链按时率 6/18；7 个交易日无发布；6 个 cron 停用；失败靠人发现未达
研究协议样本外/holdout、多重比较校正、执行成本与容量模型有 IC/t 值、19,163 样本质量库；无 walk-forward、无 BH 校正、无滑点模型未达
能力复利验证过的能力进入生产，未被验证的自动淘汰自主拓展 2 项已验证并投用；认知迭代 4,256→0半达

4. 六个结构性根因

#根因为什么会导致上面的问题证据
R1调度单点 + 无告警全部 cron 依附 Hermes gateway；gateway 不在则静默不触发；唯一 OS 兜底被禁用；失败靠翻库才发现。9/14–9/18 五日无判断；StockDailyChain=已禁用；6 个 cron 停用；failure_streak 4/7/15/18。
R2结算层不唯一同一预测/荐票在多处账本重复落盘，重跑即多一份；无 canonical key、无幂等、无版本。230 个 id / 385 条记录；105 个重复；49 个状态冲突；LHB 逐票账本停在 8/13。
R3度量层缺失只有胜率/均收，没有 R、期望值、置信区间、基准相对；无法判断 edge 是否真实，也无法做仓位。周考核只看绝对周收益；平仓 n=8；无 Sharpe/Brier；limitup/lhb 无逐日增益。
R4门禁不阻断检查结果只写进报告，不阻断发布；None 当通过；FAIL 只转“有条件放行”；测试红了无 CI。manifest 2 项 rc=None + published=true；总审 4 FAIL + 有条件放行；3 个测试失败。
R5认知无结算认知条目没有“验证规格/适用边界/到期日”，无法机械判定，于是只能堆积。4,256→0；478 条中 477 条无有效状态；验证台账停更 103 天。
R6生产无版本库改动靠镜像同步 + 手工总账；无法 bisect、无法回滚、无法评审，重构风险高。生产目录非 git；274 条手工变更；2,148/1,998 行巨石。

5. 改造路线图

按“先止血、再建度量、最后重构”排序。每项都给了可机械验收的标准；未获批准前不动手。

P0 · 48 小时止血：让失败可见、让门禁真的拦

01
启用 OS 级兜底调度，修 watchdog 交易日口径
验收：StockDailyChain 交易日 16:30 触发；watchdog 在周末/节假日不再 FAIL；连续 5 个交易日 0 静默失败。
02
失败必告警
验收：任一 cron 连续 2 次失败 → 微信/桌面推送，含 job 名、错误摘要、最后成功日；告警本身有心跳。
03
门禁硬约束：exit_code=None 视为 FAIL；总审发布门禁含 FAIL 不得 publish
验收：构造一次 rc=None 的发布，必须被拒绝；manifest 里不再出现 published=true + 非零/空 rc 并存。
04
测试进发布链
验收：发布前跑 pytest -m "not network"，3 个红灯先修或标 xfail(reason)；红则拒绝发布；夜间定时跑全量。
05
清 staging + 保留策略
验收：.review_staging 降到 <500MB；保留最近 14 天；磁盘水位 >80% 告警。

P1 · 2 周建度量：把“判断”变成“可结算资产”

06
唯一结算账本（canonical settlement ledger）
验收：每条预测/荐票一个不可变 ID，一行 canonical 结果；重算写 version+supersedes；对 105 个重复 id 做一次性归并；给出“重复率=0、冲突率=0”的报告。
07
统计层：R 倍数 / 期望值 / 置信区间 / Brier
验收：每路输出 n、胜率、均收、R、期望值、bootstrap 95% CI、Brier；周考核改为“基准相对 + 最小样本 n≥30 才判合格”，空仓不计合格。
08
预测可判定率 ≥70%
验收：模板强制 field/op/threshold/容差；ambiguous+unverifiable 合计 ≤30%；每条预测在 due_d 后 1 个交易日内自动结算。
09
认知清算：4,256 → 可验证子集
验收：每条认知必须有“验证规格 + 适用边界 + 到期日”；无规格的归档不进判断；每周机械验证一次，产出“新增/淘汰/转能力”三张清单。
10
总审指派看板
验收：165 条指派全部有 owner/due/验收标准；逾期 3 日自动升级；完成率 ≥80%。

P2 · 6 周上台阶：从“能跑”到“顶级工程”

11
研究协议：walk-forward + holdout + 多重比较校正
验收：因子/规则全部走时间切分样本外；BH 校正后仍显著的才进生产；因子库带版本号与失效日期。
12
执行模型：滑点 / 成交概率 / 容量
验收：结算价改为“可成交价”分布（一字=不可买、封单不足=部分成交）；输出容量上限；模拟盘与实盘口径一致。
13
架构拆包 + 生产入 git
验收：review_pages/review_publish 拆到 <600 行/模块；删除 56 个死脚本；生产目录 git 化，pre-commit 跑测试与语法检查。
14
可观测性面板
验收：每源新鲜度/延迟、日链甘特、发布 SLA、失败 Top5；执行历史保留 ≥1 年；季度可靠性复盘有数据。

6. 如果只做三件事

1. 唯一结算账本 + 统计层
